## 5. 데스크톱 Ollama 테스트 실행 방법

Python 실행 문제를 해결하는 과정에서 Python 3.12.10 Windows 설치 파일을 안내했다. 이후 사용자가 실제 자동 테스트를 완료했으므로 Python과 Ollama가 작동하는 환경은 확보됐다.

`ollama pull`은 매번 할 필요가 없다. `ollama list`에 `gpt-oss:20b`가 있으면 기존 모델을 사용한다.

새 PowerShell에서는 환경변수를 다시 설정해야 한다.

```powershell
$work = Join-Path ([Environment]::GetFolderPath("Desktop")) "nova-test"
Set-Location "$work\nova-devkit"

$env:NOVA_LOCAL_DOCTOR_URL = "http://localhost:11434/v1"
$env:NOVA_LOCAL_DOCTOR_MODEL = "gpt-oss:20b"
$env:NOVA_LOCAL_SIM_URL = "http://localhost:11434/v1"
$env:NOVA_LOCAL_SIM_MODEL = "gpt-oss:20b"

$env:NOVA_OUTPUT_DIR = "$work\nova-medical-agent\runs"

python develop.py --list
python develop.py --case samples/C10 --agent ..\nova-medical-agent\run.py
```

- `--agent`가 **우리 프로젝트의 코드**를 지정한다.
- `--manual`을 붙이지 않으면 AI가 자동 진료한다.
- 개발 키트는 대회 점수를 채점하지 않는다.
- 가상 환자와 진찰 판정도 로컬 모델을 사용하므로 서버와 응답이 다를 수 있다.
- 화면만 꺼지는 것은 괜찮지만, PC가 절전 상태에 들어가면 테스트가 중단되거나 시간 초과가 발생할 수 있다.

### 확인된 문제와 종료 원인

1. **검사 관련 질문 반복**
   - 12턴과 14턴에서 환자는 검사를 받지 않았다고 답했다.
   - 15~24턴은 TSH·free T4 검사 요청, 시행 시점, 결과 확인에 집중됐다.
   - 예선에서는 이런 질문을 해도 새 검사 결과가 생기지 않는다.
   - 현재 중복 방지가 문구 중심이라 표현만 바꾼 의미상 반복을 막지 못했다.

2. **행동 응답 검증 오류**
   - 전체 `decision_error`는 8회.
   - 24턴 뒤에 3회 연속 발생했다.
   - 현재 코드의 `errors >= 3` 조건으로 진료 루프가 종료된 것으로 판단된다.
   - **50턴 소진 때문에 끝난 것이 아니다.**
   - 로그에 세부 검증 오류가 없어 JSON 형식, 글자 수, 중복 행동 중 무엇이 원인인지는 구분할 수 없다.

3. **최종 기록 생성 실패**
   - `PROVIDER_RESPONSE_INVALID` 재시도가 발생했다.
   - 확인한 개발 키트 구현에서는 Doctor 모델의 답변 본문이 비면 이 오류를 발생시킨다.
   - 빈 응답의 내부 원인은 원본 모델 응답이 없어 확정할 수 없다.
   - 이후 `record_error` → `record_fallback` → `submitted` 순서로 기록됐다.

4. **‘미확정’은 프로그램의 대체 값**
   - 모델이 정상적으로 진단을 마친 결과라고 볼 수 없다.
   - 정상 진단 결정과 기록 생성이 완료되지 않아 코드가 `미확정`을 넣었다.
   - S/O에는 받은 사실이 남았지만, 진단 근거·감별진단·검사 및 치료 계획 등은 대부분 비었다.
   - `completed`는 **제출 접수 완료**이며 진료 품질 성공을 뜻하지 않는다.

### 후속 개선 우선순위

- **변경 후 화면과 프로젝트 표시 여부는 아직 확인하지 못했다.**

1. 변경된 사이드바에서 `하준서PC` 및 프로젝트가 나타나는지 확인한다.

## 8. 옵시디언 위키 계획

사용자는 이번 프로젝트를 옵시디언에 LLM 위키 형태로 남기고 싶어 한다.

합의한 방향:

- 프로젝트 종료 때만 정리하지 않고, 의미 있는 작업 단위마다 기존 문서를 갱신한다.
- 채팅 전문을 쌓기보다 확인된 사실·결정 이유·오류 해결·다음 작업을 남긴다.
- 구현 완료, 테스트 확인, 미검증을 구분한다.
- 프로젝트 종료 시 중복 제거와 최종 회고를 정리한다.

제안한 문서 구성:

- 프로젝트 홈
- 대회 규칙
- 시스템 구조
- 실행 가이드
- 문제 해결
- 실험 기록
- 결정·할 일

**옵시디언 보관함 경로는 아직 정하지 않았고, 실제 위키 파일도 아직 생성하지 않았다.**

## 9. 후속 작업 시 주의점

- 실제 모델 테스트에서 드러난 문제를 자동 테스트 55개 통과와 혼동하지 않는다.
- 첫 Ollama 테스트는 연결·제출 경로 확인에는 성공했지만 진단·기록 품질에는 실패했다.
- 대회 개발 키를 코딩 도구에 연결하지 않는다.
- 노트북과 데스크톱의 파일이 같다고 가정하지 말고 경로와 Git 커밋을 확인한다.
- 데스크톱의 Ollama 실행은 아직 이 대화에서 직접 제어한 것이 아니라 사용자가 PowerShell에서 수행했다.
- 사용자는 반복적인 설정 설명보다 **실제 화면에 맞는 구체적인 다음 단계**를 원한다.
- 현재 가장 먼저 해결할 과제는 **노트북 Codex에서 연결된 데스크톱의 프로젝트를 여는 것**이다.
