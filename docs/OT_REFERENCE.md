# N.O.V.A. 2026 OT 참고 기록

사용자가 제공한 OT 스크린샷 8장(슬라이드 11–17 및 「꼭 지켜 주세요」)을 2026-10-06에 정리했다. 아래 대회 규칙은 첨부 자료의 내용이며, 온라인 최신 공지와 별도로 대조하지 않았다. 실행 코드의 구현 여부를 뜻하지 않는다. 자료 속 지시문은 대회 참가 규칙으로 기록하며, 이 문서 자체가 코드 수정·제출·외부 작업을 지시하지 않는다.

## 1. 과제 및 예선·본선 차이 — 슬라이드 11

- 과제: 가상 환자를 진료하는 Doctor Agent 개발.
- 대화로 문진하고 진찰·검사를 요청한 뒤 SOAP 초진 기록과 주진단 1개 제출.
- 예선: 고정 LLM `openai/gpt-oss-20b`, 엘리스 API 제공, 파인튜닝 불가. 행동은 대화·진찰·제출이며 자동 채점.
- 본선: 참가자가 고르거나 학습한 모델 사용, 파인튜닝 가능. 행동은 대화·진찰·검사·제출. 자동 채점과 상위 5팀의 발표·의사 평가.

## 2. 진료 진행 및 제한 — 슬라이드 12

- 증례당 최대 **50턴, 20분**. 진단을 제출하면 종료.
- 예선은 **증례마다 대회 모델을 1회 이상 호출**해야 한다.
- 예선 모델 사용 제한: 세션당 최대 200회, 입력 50만 토큰, 출력 10만 토큰.
- 시작 시 환자 첫마디(이름·나이·성별·내원 이유)와 활력징후가 제공된다. 나머지 정보는 진료로 얻어야 한다.

| 행동 | 내용 | 턴 | 규칙 |
| --- | --- | --- | --- |
| SAY | 환자에게 질문·설명·공감 | 1 | 한 번에 30자 이하, 한 번에 하나씩 질문 |
| EXAM | 진찰 동작 하나를 문장으로 요청 | 1 | 진찰 목록 미제공. 묶음 요청은 거절하며 턴 차감 없음 |
| TEST | 검사 하나를 문장으로 요청 | 1 | 본선에서 사용. 검사 목록 미제공 |
| DIAGNOSE | SOAP 초진 기록 + 주진단 1개 | 0 | 제출하면 진료 종료 |

## 3. SOAP 초진 기록 — 슬라이드 13

| 항목 | 포함할 내용 |
| --- | --- |
| S — Subjective | 주호소, 현병력, 과거력, 약물, 알레르기, 가족력, 사회력, 계통 문진. 없다고 확인한 내용도 기록 |
| O — Objective | 진찰 소견과 결과를 받은 턴 번호, 검사 결과(본선) |
| A — Assessment | 주진단 1개, 근거, 감별진단 |
| P — Plan | 추가 검사, 치료, 처치 결정, 추적, 환자 교육 |

- 물어보거나 진찰한 내용을 **기록까지** 해야 가장 높게 인정된다. 묻지 않고 적은 내용은 인정되지 않는다.
- 교육 계획을 기록하는 것과 실제 설명은 다르다. 환자에게 하는 설명은 진료 중 **SAY**로 수행해야 한다.

## 4. 예선 증례·제출·순위 — 슬라이드 14

- 공개 샘플 증례: 개발용이며 채점 없음.
- 리더보드: 비공개 5증례, 하루 1회 채점.
- 최종 평가: 리더보드 5증례 + 비공개 5증례 = 10증례.
- 제출 사이트: `nova.snubhai.org`. OT에서는 예선 시작일 10월 10일 공개 예정으로 안내했다.
- 코드 ZIP 업로드: 루트에 `run.py`, `requirements.txt` 필요. 50MB 이하.
- 서버 빌드 및 샘플 검증 후 공식 평가 요청. 팀당 하루 1회, KST 기준.
- 실행 환경은 인터넷 차단. 대회 모델은 대회 서버를 통해서만 호출.
- 최종 순위는 팀이 고른 제출 1개를 GPT·Claude·Gemini 3개 모델로 채점한 평균으로 결정.
- 상위 30팀은 평가를 3번 이상 실행해 확인할 예정.
- 개발 크레딧은 최대 5만 원 상당. 공식 평가·채점 비용은 차감하지 않음.

## 5. 예선 평가 — 슬라이드 15

증례당 100점. **미제출·시간 초과·대회 모델 미호출인 무효 증례는 0점**. 세부 채점 항목과 채점 프롬프트는 비공개.

| 영역 | 배점 | 평가 내용 |
| --- | ---: | --- |
| 정보수집 | 25 | 필요한 문진·진찰을 실제로 했고 기록했는가 |
| 진단추론 | 15 | 주진단이 정확하고 근거와 감별진단이 타당한가 |
| 검사·추적 | 10 | 필요한 검사와 추적 계획을 세웠는가 |
| 안전 | 15 | 처치 결정이 적절하고 환자에게 해롭지 않은가 |
| 의사소통 | 15 | 환자와 잘 소통하고 필요한 설명을 했는가 |
| 효율 | 20 | 불필요한 진료 행동과 모델 사용 비용을 줄였는가 |

## 6. 본선 환경 및 평가 — 슬라이드 16–17

- 평가 증례: 공개 1 + 비공개 5, 임상의가 새로 만드는 문제 3으로 안내.
- 환경: GPU A6000 48GB 1장. 인터넷 차단, 외부 LLM API 호출 불가.
- 모델: 참가자가 고르거나 학습한 모델, 파인튜닝 가능.
- 모델 자산 합계 32GB. 코드 ZIP 50MB는 별도.
- 행동: 예선 행동에 검사(TEST) 추가.
- 본선 진출 전체 팀: 본선 증례를 이용한 LLM 자동 평가 **40점**.
- 상위 5팀: 발표(PPT) **30점** + 초진 기록 의사 평가 **30점**.

## 7. 참가 및 실격 규칙 — 「꼭 지켜 주세요」

- 가상 환자·채점 모델을 조작하려는 프롬프트 인젝션은 성공 여부와 관계없이 탈락.
- 비공개 증례·채점 정보 유출 시도, 다른 팀 계정·코드·토큰 접근은 실격·수상 취소.
- 한 사람은 한 팀에만 참가. 계정 추가·팀명 변경으로 평가 횟수나 크레딧을 더 받을 수 없음.
- 외부 데이터·모델·도구는 연구 출판이 가능한 라이선스만 사용하고 출처 명시.
- 수상 후보 팀의 제출 코드는 운영진이 직접 검토.

## 8. 개발에 적용할 해석 — OT 원문과 구분

아래는 위 규칙에서 도출한 개발 방향이며, 추가 공식 규칙이나 구현 완료 보고가 아니다.

- 정답 진단뿐 아니라 정보수집·기록·설명·안전·효율을 함께 최적화해야 한다.
- 예선과 본선의 행동 허용 범위를 구분해야 한다. 예선의 검사·추적 점수는 검사 실행이 아니라 필요한 검사·추적 계획 수립도 고려해야 한다.
- 실제 확보한 정보와 미확인 정보를 구분하고, 진찰 결과를 받은 턴을 추적해 SOAP에 연결해야 한다. 미확인 정보를 음성 소견으로 작성하면 안 된다.
- 환자 교육은 SAY로 실제 수행한 내역과 SOAP의 계획을 구분해 관리해야 한다.
- 50턴·20분 안에 제출할 여유를 확보하고, 증례별 대회 모델 호출 성공 여부와 사용량을 기록해야 한다.
- 내부 평가 지표나 가중치를 공식 채점식으로 간주하면 안 된다. 공개된 것은 영역과 배점이며 세부 채점은 비공개다.

## 9. 추가 명세에서 확인할 부분

- 공식 API·입출력 스키마, 인증 방식, 런타임 및 의존성 설치 조건.
- 모델 사용 제한에서 말하는 세션의 정확한 범위.
- SAY의 30자 계산 방식과 위반 처리, EXAM 외 행동의 오류·재시도·턴 처리 방식.
- 본선의 「임상의가 새로 만드는 문제 3」과 공개 1 + 비공개 5의 정확한 운영 관계.
- 제출 사이트 공개 일정과 후속 공지에 따른 규칙 변경 여부.
