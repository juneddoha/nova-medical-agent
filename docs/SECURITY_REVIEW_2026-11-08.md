# 게시 범위·민감정보 점검 — 2026-11-08 KST

GitHub `juneddoha/nova-medical-agent`의 기존 비공개 설정을 유지한다. 연결된 GitHub 계정과 저장소 소유자가 모두 `juneddoha`이며 같은 계정 ID인 것을 GitHub 연결 도구로 확인했다. 해당 계정의 push/admin 권한도 확인했다. 사용자의 GitHub 최신화 요청에 따라 최신 활성 소스·테스트·공개용 검증 보고서·재현 예시만 반영하며, 실제 진료·외부 연락·대회 제출은 하지 않는다.

## 게시용 정리

- `.env`·환경별 파일, 키/인증서, 로그, `runs/`, ZIP·개인 인계 묶음은 게시하지 않는다. `.env.example`에는 빈 값과 환경변수 이름만 둔다.
- 개인 사용자 디렉터리·호스트명이 있는 내부 문서·메타데이터는 게시 대상에서 제외한다. 원본 실행 기록·개인 인계·팀원 원본·이전 MK2·기존 ZIP은 로컬에 보존한다.
- `tests/fixtures/observed_say_delivery.json`의 실제 요청·이벤트 UUID 3곳은 관계가 일치하도록 결정적 가상 UUID로 교체한다. 환자 대화는 대회 **공개 가상 증례**의 로컬 회귀 입력이며 실환자 정보가 아니다.
- 내부 대화 인계 문서 `CHAT_CONTEXT_*`, `HANDOFF_*`, `TRANSFER_*`, 운영용 `AGENTS.md`, `PROJECT_MEMORY.md`, 규정 메모리와 보관용 `references/`는 게시에서 제외한다. 이전 비활성 `src/`·`simulator/` 및 기존 내부 인계 문서도 최신 트리에서는 제거하며 로컬 원본과 과거 Git 커밋은 보존한다.
- `.gitignore`·`.dockerignore`에 민감 파일·로그·개인 묶음 제외 규칙을 보완한다. 검사·예시·대회 회귀 입력이 제출용 Docker 문맥에 불필요하게 포함되지 않도록 한다.

## 검사 결과와 한계

게시할 전체 텍스트 파일과 기존 로컬 Git 이력 **8커밋 / 중복을 제외한 81개 blob**을 검사했다. 개인키 헤더, 주요 공급자 토큰, JWT, 인증정보가 든 URL, 리터럴 키·비밀번호, 이메일·휴대전화·주민번호 형태를 점검해 **탐지 결과 0건**을 확인했다. 현재 환경의 민감 변수 값이 게시 파일에 포함되지 않는지도 값 출력 없이 대조했다. 패턴 검사로 임의 형식의 모든 비밀이나 자연어 개인정보의 부재를 증명할 수는 없다.

원시 실행 로그·ZIP은 보존만 하며 GitHub로 전송하지 않는다. 비밀 값이나 탐지된 원문은 검사 출력·보고서에 쓰지 않는다. 게시용 익명화 사본에서 전체 161개 회귀 검사를 다시 실행해 ID 교체 뒤에도 검사 관계가 유지되는지 확인한다.

과거 Git 이력은 강제로 덮어쓰지 않는다. 이력에서도 위 비밀 패턴은 탐지되지 않았지만, 최신 `.gitignore`는 과거 커밋을 제거하지 않는다. 이번 작업의 개인정보 정리는 게시할 최신 트리에 적용된다. 저장소 소유자 GitHub ID와 기존 Git 커밋 저자 메타데이터는 유지한다.
